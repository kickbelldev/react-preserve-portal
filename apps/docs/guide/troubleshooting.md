# 문제 해결

## 콘텐츠가 보이지 않아요

`slotKey`의 초기값은 `null`입니다. `setSlotKey('main')`을 호출했는지, 해당 키의 Slot이 마운트됐는지 확인하세요. 선택만 하고 목적지가 없으면 콘텐츠는 분리된 컨테이너에 남습니다.

선택과 등록을 구분해서 확인하세요. `slotKey`가 `null`일 수 있으므로 먼저 검사합니다.

```tsx
const { slotKey, targets } = Player.usePortal()
const target = slotKey === null ? undefined : targets.get(slotKey)
// target이 없으면 등록된 목적지가 없습니다.
// target?.isConnected로 문서 연결 여부를 확인할 수 있습니다.
```

여기서 `Player`는 앱에서 정의한 포털입니다. 연결된 요소도 CSS에 의해 숨겨질 수 있습니다. 목적지나 부모의 CSS가 `display: none`이거나 크기가 0인 경우도 확인합니다. 개발자 도구에서 포털 컨테이너를 직접 이동하면 라이브러리 상태와 DOM이 어긋날 수 있습니다.

## 이동하면 상태가 초기화돼요

- 팩토리가 컴포넌트 함수 안에서 실행되는지 확인하세요.
- 이동 중 Host가 조건부 렌더링으로 사라지거나 key가 바뀌는지 확인하세요.
- Host 안의 컴포넌트 타입 또는 key가 바뀌는지 확인하세요.
- 라우트 공통 레이아웃이 실제로 유지되는지 확인하세요.

개발 환경의 Strict Mode는 Effect 설정과 정리를 추가 실행할 수 있습니다. 이것과 실제 이동 시 재마운트를 구분하세요. uncontrolled 입력값과 DOM 객체 참조를 함께 검사하면 원인을 찾기 쉽습니다.

## iframe이 새로 로드되거나 포커스가 사라져요

같은 DOM 노드를 유지하는 것만으로 브라우저 내부 상태를 보장하지는 않습니다. `moveBefore` 지원 여부, 이동 전 양쪽의 `isConnected`, 같은 `ownerDocument`인지 확인하세요. 출발 Slot을 먼저 제거하거나 콘텐츠를 숨기면 연결 보존 조건이 깨집니다.

iframe의 교차 출처 콘텐츠는 앱에서 내부 상태를 직접 검사할 수 없을 수 있습니다. 실제 지원 브라우저와 플레이어로 확인하세요. [브라우저 API와 대안](./web-platform)에 상세 조건이 있습니다.

## 숨겼는데 타이머나 미디어가 계속 실행돼요

포털 자체의 숨기기는 React 언마운트가 아닙니다. 콘텐츠에서 `slotKey === null`을 관찰해 필요한 작업을 멈추거나, 별도의 재생 상태를 관리하세요. `slotKey !== null`도 실제 화면 가시성을 뜻하지는 않습니다. [비디오 플레이어](./video-player)에 닫을 때 일시정지하는 전체 예제가 있습니다.

## `reset()` 이후 다시 표시하고 싶어요

0.3.0부터 등록된 Slot이 유지됩니다. `setSlotKey('main')`만 호출하면 됩니다. 내부 콘텐츠의 상태 자체를 초기화하려면 콘텐츠에 명시적 초기화 액션을 제공하거나 key를 변경해 의도적으로 재마운트하세요.

## 대상 등록이 덮어써져요

같은 포털 ID와 슬롯 키를 여러 곳에서 사용하는지 확인하세요. 마지막 등록이 우선이고, 그 Slot이 사라지면 아직 등록된 이전 Slot으로 돌아갑니다. 개발 빌드의 콘솔 경고도 확인해 보세요. 외부 등록은 [반환된 정리 함수](../api#external-targets)를 사용하세요. `targets` Map을 직접 수정하면 알림과 정리가 동작하지 않습니다.

## 재생 버튼과 실제 영상 상태가 달라요 {#playback-state}

네이티브 `play`, `pause`, `ended` 이벤트를 재생 상태의 기준으로 삼으세요. `play()`가 반환하는 Promise도 처리해야 합니다. 자동 재생 정책, 소스 변경, 네트워크 오류로 거부될 수 있으므로 클릭할 때 단순히 boolean을 뒤집으면 안 됩니다. 닫기 전에 명시적으로 일시정지하고 소스 변경·언마운트 뒤 도착한 이전 재생 결과는 무시하세요. DOM 객체가 유지돼도 분리된 영상은 브라우저가 일시정지할 수 있습니다. 문서의 실제 예제는 MP4와 WebM 파일을 사용하고 재생 실패 후 재시도를 처리합니다. [비디오 가이드](./video-player)는 기본 컨트롤을 사용하는 간단한 구성을 설명합니다.

## CommonJS에서 NodeNext 타입 오류가 나요

설치한 라이브러리 버전을 확인하세요. 0.4.1은 `require` 경로에 `.d.cts` 선언을 제공해 0.4.0의 선언 형식 불일치를 수정했습니다. 별도의 타입 우회 코드를 넣기 전에 패키지를 업그레이드하세요. [마이그레이션 안내](../migration)를 참고하세요.
