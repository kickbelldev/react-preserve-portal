# 문제 해결

## 콘텐츠가 보이지 않아요

`slotKey`의 초기값은 `null`입니다. `setSlotKey('main')`을 호출했는지, 해당 키의 Slot이 마운트됐는지 확인하세요. 선택만 하고 목적지가 없으면 콘텐츠는 분리된 컨테이너에 남습니다.

`targets.has(slotKey)`로 등록을 확인할 수 있습니다. 등록된 요소가 실제 문서에 붙어 있는지도 확인하세요. 목적지나 부모의 CSS가 `display: none`이거나 크기가 0인 경우도 확인합니다. 개발자 도구에서 포털 컨테이너를 직접 이동하면 라이브러리 상태와 DOM이 어긋날 수 있습니다.

## 이동하면 상태가 초기화돼요

- 팩토리가 컴포넌트 함수 안에서 실행되는지 확인하세요.
- 이동 중 Host가 조건부 렌더링으로 사라지거나 key가 바뀌는지 확인하세요.
- Host 안의 컴포넌트 타입 또는 key가 바뀌는지 확인하세요.
- 라우트 공통 레이아웃이 실제로 유지되는지 확인하세요.

개발 환경의 Strict Mode는 Effect 설정과 정리를 추가 실행할 수 있습니다. 이것과 실제 이동 시 재마운트를 구분하세요. uncontrolled 입력값과 DOM 객체 참조를 함께 검사하면 원인을 찾기 쉽습니다.

## iframe이 새로 로드되거나 포커스가 사라져요

DOM 정체성 보존만으로 브라우저 내부 상태를 보장하지는 않습니다. `moveBefore` 지원 여부, 이동 전 양쪽의 `isConnected`, 같은 `ownerDocument`인지 확인하세요. 출발 Slot을 먼저 제거하거나 콘텐츠를 숨기면 연결 보존 조건이 깨집니다.

iframe의 교차 출처 콘텐츠는 앱에서 내부 상태를 직접 검사할 수 없을 수 있습니다. 실제 지원 브라우저와 플레이어로 확인하세요. [최신 Web API](./web-platform)에 상세 조건이 있습니다.

## 숨겼는데 타이머나 미디어가 계속 실행돼요

정상 동작입니다. 숨기기는 React 언마운트가 아닙니다. 콘텐츠에서 `slotKey === null`을 관찰해 필요한 작업을 멈추거나, 별도의 재생 상태를 관리하세요. `slotKey !== null`도 실제 화면 가시성을 뜻하지는 않습니다.

## `reset()` 이후 다시 표시하고 싶어요

0.3.0부터 등록된 Slot이 유지됩니다. `setSlotKey('main')`만 호출하면 됩니다. 내부 콘텐츠의 상태 자체를 초기화하려면 콘텐츠에 명시적 초기화 액션을 제공하거나 key를 변경해 의도적으로 재마운트하세요.

## 대상 등록이 덮어써져요

같은 포털 ID와 슬롯 키를 여러 곳에서 사용하는지 확인하세요. 마지막 등록이 우선입니다. 외부 등록은 [반환된 정리 함수](../api#외부-dom-목적지-등록)를 사용하세요. `targets` Map을 직접 수정하면 알림과 정리가 동작하지 않습니다.

## 재생 버튼과 실제 영상 상태가 달라요

네이티브 `play`, `pause`, `ended` 이벤트를 재생 상태의 기준으로 삼으세요. `play()`가 반환하는 Promise도 처리해야 합니다. 자동 재생 정책, 소스 변경, 네트워크 오류로 거부될 수 있으므로 클릭할 때 단순히 boolean을 뒤집으면 안 됩니다. 닫기 전에 명시적으로 일시정지하고 소스 변경·언마운트 뒤 도착한 이전 재생 결과는 무시하세요. DOM 객체가 유지돼도 분리된 영상은 브라우저가 일시정지할 수 있습니다. 저장소 데모는 이 경로를 처리하며 로컬 canvas 스트림으로 검증합니다.
