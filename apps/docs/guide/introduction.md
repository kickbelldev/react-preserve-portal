# 소개

React Preserve Portal은 **이미 만들어진 DOM 인스턴스를 다시 만들지 않고 다른 자리로 옮기는 라이브러리**입니다. 재생 중인 `<video>`, 로드된 `<iframe>`, WebGL 캔버스, 에디터를 본문에서 미니플레이어나 다른 패널로 보내도 같은 DOM 노드를 그대로 씁니다. 노드를 새로 만들지 않으니 그 안의 React 컴포넌트도 다시 마운트되지 않고, 컴포넌트 상태와 Effect도 그대로 이어집니다.

## 어떤 문제를 해결하나요?

본문용 `<VideoPlayer />`와 미니플레이어용 `<VideoPlayer />`를 따로 렌더링하면 서로 다른 인스턴스가 됩니다. 한쪽을 지우고 다른 쪽을 만들면 컴포넌트와 DOM 노드가 모두 새로 만들어집니다.

React 상태는 스토어로 끌어올리면 다시 마운트돼도 복원할 수 있습니다. 하지만 **DOM 인스턴스가 가진 상태는 그렇게 옮길 수 없습니다.**

- `<video>`가 이미 받아 둔 데이터와 디코더 상태
- `<iframe>` 안에 로드된 문서
- `<canvas>`의 WebGL 컨텍스트
- 지도나 에디터 라이브러리가 직접 만든 DOM
- 입력 중인 글자의 커서·선택 범위와 스크롤 위치

이런 상태는 노드를 다시 만들면 처음부터 다시 로드되거나 끊깁니다. 지키려면 같은 노드를 그대로 옮기는 수밖에 없고, 이 라이브러리가 그 일을 합니다.

사용법은 간단합니다. 콘텐츠를 **Host에 한 번** 넣고, **Slot으로 표시할 위치**를 지정합니다. 위치를 바꾸면 콘텐츠를 새로 만드는 대신 콘텐츠를 담은 컨테이너 노드를 옮깁니다.

| 구성 요소            | 할 일                                                                         |
| -------------------- | ----------------------------------------------------------------------------- |
| `createPortal()`     | 이름과 슬롯 목록을 정해 하나의 포털을 만듭니다. 컴포넌트 바깥에서 호출합니다. |
| `Player.Host`        | 유지할 콘텐츠를 렌더링합니다. 보통 포털마다 하나를 사용합니다.                |
| `Player.Slot`        | `main`, `mini` 같은 표시 위치를 등록합니다. Slot 자체는 비워 둡니다.          |
| `Player.usePortal()` | 현재 선택한 슬롯을 읽고 `setSlotKey()`로 위치를 바꿉니다.                     |

한 포털의 두 Slot은 서로 다른 표시 위치입니다. 두 개의 플레이어를 만드는 구성이 아닙니다.

## React DOM의 `createPortal`과 무엇이 다른가요?

React DOM의 `createPortal(children, target)`은 콘텐츠를 `target`에 렌더링합니다. 위치를 옮기려고 `target`을 다른 노드로 바꾸면, React는 이를 다른 포털로 보고 콘텐츠를 **언마운트한 뒤 다시 마운트**합니다. DOM 노드와 컴포넌트 상태가 모두 새로 만들어집니다.

이 라이브러리는 React DOM에 항상 같은 컨테이너를 전달하고, 그 **컨테이너 노드 자체를 Slot 사이로 옮깁니다.** React 입장에서는 렌더링 대상이 바뀌지 않으니 다시 마운트할 이유가 없고, 브라우저 입장에서는 같은 노드가 자리만 옮깁니다. React context와 이벤트는 Host를 기준으로 이어집니다. 구체적인 동작은 [보존 원리와 수명](./preservation)에서 설명합니다.

## 사용하기 좋은 경우

- 재생 중인 영상을 처음부터 다시 받지 않고 미니플레이어로 보내야 할 때
- iframe, WebGL 캔버스, 지도처럼 다시 만들기 비싼 요소를 다른 패널로 옮길 때
- 에디터를 옮기면서 입력 중인 내용과 커서 위치를 지켜야 할 때
- 라우트가 바뀌어도 같은 위젯을 유지하고, 표시 위치만 바꿔야 할 때

CSS Grid나 Flex로 화면 배치만 바꿀 수 있다면 DOM을 옮길 필요가 없습니다. 모달·팝오버나 같은 자리의 탭 표시에는 다른 도구가 더 간단할 수 있습니다. [브라우저 API와 대안](./web-platform)에서 필요한 동작별로 비교할 수 있습니다.

## 사용 전에 알아둘 것

Host를 언마운트하거나 콘텐츠의 `key`를 바꾸면 일반 React 규칙에 따라 상태가 사라집니다. 라우팅 중에도 유지하려면 Host를 공통 레이아웃에 두세요.

같은 DOM 노드를 유지해도 모든 브라우저에서 포커스·iframe·재생 상태가 유지되는 것은 아닙니다. 연결된 이동의 브라우저 지원과 숨김 동작은 [보존 범위](./preservation#preserved-state)를 참고하세요.

React와 React DOM **18 이상**이 필요하며, TypeScript를 사용한다면 **5 이상**이 필요합니다. ESM과 CommonJS를 제공합니다.

[빠르게 시작하기](./quick-start)에서 설치하고 첫 포털을 만들어 보세요.
