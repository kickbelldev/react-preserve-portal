# 소개

React Preserve Portal은 **하나의 React 컴포넌트를 여러 DOM 위치로 옮기는 라이브러리**입니다. 본문의 비디오를 미니플레이어로 보내거나 에디터를 다른 패널로 옮길 때, 같은 DOM 노드와 컴포넌트 상태를 유지합니다.

## 어떤 문제를 해결하나요?

본문용 `<VideoPlayer />`와 미니플레이어용 `<VideoPlayer />`를 따로 렌더링하면 서로 다른 인스턴스가 됩니다. 한쪽을 지우고 다른 쪽을 만들면 컴포넌트 내부 상태와 DOM 노드도 새로 만들어집니다. 상태를 상위로 옮겨 입력값을 복원할 수는 있지만, 그것만으로 원래의 `<video>`, 에디터, 캔버스가 유지되지는 않습니다.

이 라이브러리에서는 콘텐츠를 **Host에 한 번** 넣고, **Slot으로 표시할 위치**를 지정합니다. 이동할 때 콘텐츠를 새로 만드는 대신 콘텐츠를 담은 컨테이너를 옮깁니다.

| 구성 요소            | 할 일                                                                         |
| -------------------- | ----------------------------------------------------------------------------- |
| `createPortal()`     | 이름과 슬롯 목록을 정해 하나의 포털을 만듭니다. 컴포넌트 바깥에서 호출합니다. |
| `Player.Host`        | 유지할 콘텐츠를 렌더링합니다. 보통 포털마다 하나를 사용합니다.                |
| `Player.Slot`        | `main`, `mini` 같은 표시 위치를 등록합니다. Slot 자체는 비워 둡니다.          |
| `Player.usePortal()` | 현재 선택한 슬롯을 읽고 `setSlotKey()`로 위치를 바꿉니다.                     |

한 포털의 두 Slot은 서로 다른 표시 위치입니다. 두 개의 플레이어를 만드는 구성이 아닙니다.

## React DOM의 `createPortal`과 무엇이 다른가요?

React DOM의 `createPortal(children, target)`은 콘텐츠를 `target`에 렌더링합니다. `target`으로 다른 DOM 노드를 전달하면 포털 콘텐츠가 다시 생성됩니다.

이 라이브러리는 React DOM에 항상 같은 컨테이너를 전달합니다. **React가 렌더링하는 대상은 고정되고, 컨테이너가 들어갈 Slot만 바뀝니다.** React context와 컴포넌트 상태는 Host를 기준으로 이어집니다. 구체적인 동작은 [보존 원리와 수명](./preservation)에서 설명합니다.

## 사용하기 좋은 경우

- 재생 화면과 미니플레이어가 하나의 비디오 요소를 공유해야 할 때
- 에디터나 캔버스를 패널 사이에서 옮기면서 내부 상태를 유지해야 할 때
- 라우트가 바뀌어도 같은 위젯을 유지하고, 표시 위치만 바꿔야 할 때

CSS Grid나 Flex로 화면 배치만 바꿀 수 있다면 DOM을 옮길 필요가 없습니다. 모달·팝오버나 같은 자리의 탭 표시에는 다른 도구가 더 간단할 수 있습니다. [브라우저 API와 대안](./web-platform)에서 필요한 동작별로 비교할 수 있습니다.

## 사용 전에 알아둘 것

Host를 언마운트하거나 콘텐츠의 `key`를 바꾸면 일반 React 규칙에 따라 상태가 사라집니다. 라우팅 중에도 유지하려면 Host를 공통 레이아웃에 두세요.

같은 DOM 노드를 유지해도 모든 브라우저에서 포커스·iframe·재생 상태가 유지되는 것은 아닙니다. 연결된 이동의 브라우저 지원과 숨김 동작은 [보존 범위](./preservation#preserved-state)를 참고하세요.

React와 React DOM **18 이상**이 필요하며, TypeScript를 사용한다면 **5 이상**이 필요합니다. ESM과 CommonJS를 제공합니다.

[빠르게 시작하기](./quick-start)에서 설치하고 첫 포털을 만들어 보세요.
